## 2. Invariants & Guardrails

1. **Sequential Lifecycle Ordering:** Actions must proceed in exact sequence:
   $$\text{Approved} \longrightarrow \text{Prepare} \longrightarrow \text{Print} \longrightarrow \text{Sign} \longrightarrow \text{Deliver / Completed}$$
   Calling any action out of sequence is rejected by backend with 400 Bad Request.
2. **Version Immutability:** `certifiedVersion` is strictly locked to `Number(approvedVersion)` from the complete 33-criterion version snapshot. React cannot alter `certifiedVersion`.
3. **No PDF Engine Rewrite:** React reuses the proven `certificate-pdf.js` implementation (`window.downloadTrackScoreCertificatePdf` and `window.generateCertificateHtml`).
4. **Single-Page A4 Guarantee:** The PDF output must render on exactly one A4 portrait page (794 $\times$ 1120 px) with zero margins, no cropping, and proper cleanup of temporary DOM containers.
5. **QR Code Integrity:** The QR code embedded in the PDF decodes to `${origin}/verify-certificate.html?cert=${certNumber}` and verifies successfully via public `verify-certificate` API.
6. **Payment Strictly Retired:** Certificate processing does NOT require payment, payment confirmation, or payment proof. Payment routes remain 410 Gone.
7. **Role Security:** Only Managers can perform certificate lifecycle mutations (`prepare`, `print`, `sign`, `deliver`). Assessors and Vendors are rejected with 403.
8. **Double-Submit Protection:** Every mutation disables action buttons during network transit and prevents duplicate requests.
