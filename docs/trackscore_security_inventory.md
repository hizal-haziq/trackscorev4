`manage-certificate` re-exports `issue-certificate` with identical enforcement. Express also retains `assessment-history`, `assessment-version`, `assessment-risk` and `stream-status` aliases, routing to the same handlers. `/api/health` returns a small public readiness object; `/api/config.js` and `/config.js` provide empty non-secret configuration. Their Express headers use the shared server policy.

Authentication is implemented in `auth.js` (HS256 signing and verification, required expiry, known roles, production secret enforcement); `verify-session` confirms the existing Bearer session before React/legacy protected rendering. `AuthProvider`/route guards and `/portal-guard.js` provide UI isolation, while backend handlers independently enforce authority.

Rate limiting is process-local: 600 reads or 300 mutations per endpoint/principal per ten minutes, plus the existing stricter failed-login limit. Active limiter entries are bounded at 10,000. Express additionally caps six simultaneous status streams per principal. This is NOT a distributed quota across Netlify instances.

The 140-cell direct role matrix covers 28 protected endpoint policies with Manager, Assessor, Vendor A, Vendor B and no session. Allowed cells can return validation/resource errors for an empty payload; they are not assertions that every workflow succeeds with `{}`. Positive workflows, ownership, signatures, expiry, scoring, uploads, certificates, version immutability and sentinel leakage have separate adversarial/regression checks. The browser matrix exercises all three portals under both React and legacy routes.

Residual deployment concerns are recorded in `trackscore_full_security_hardening_report.md`: live gateway limits, Atlas indexes/CAS under concurrent instances, finite serverless SSE snapshots, URL tokens, retained inline CSP compatibility, filesystem persistence, historical QA credentials and previously tracked runtime JSON.
