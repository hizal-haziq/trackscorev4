## 2. Invariants & Guardrails

1. **Phase Boundary:** Certificate actions (Prepare, Print, Sign, Deliver) and Assessor revision forms are NOT migrated in Phase C.
2. **Authoritative Backend:** All lifecycle transitions and status changes are governed strictly by the backend (`approve-evaluation.js`, `schedule-assessment.js`, `assign-assessor.js`).
3. **Immutability:** Technical criterion scores, points, and assessor comments remain strictly read-only and uneditable by Manager.
4. **Retired Payment:** Payment routes remain 410 Gone. Approval transitions directly to certificate readiness without any payment prerequisites or data creation.
5. **Mutation Safety:** Every mutation uses a single active submission lock, disables buttons during flight, handles 401/403/404/409/422/500 cleanly, and cancels or prevents stale responses from overwriting active state.
6. **No Auto-Retry on Alternate Prefix:** Mutation requests (`POST`) are never re-sent to an alternate URL prefix.
